# Task02 第二章 智能体发展史：一部"痛点驱动"的接力史

> 学习项目：[datawhalechina/hello-agents](https://github.com/datawhalechina/hello-agents)
> 日期：2026-09-16
> 任务：理解智能体从符号主义到 LLM 智能体的演进脉络，搞清每次范式更替到底在解决什么问题

昨天跑通第一个 Agent 之后，我一直有个疑问：为什么现在的智能体长成"LLM + 工具 + 循环"这个样子？今天这一章算是把答案给我了。

读完最大的感受是，**AI 这七十年不是一路进步过来的，而是一路"打补丁"过来的**。每一代范式都是被上一代的死结逼出来的，而它自己又埋下新的死结。抓住这条链，整章就不用背了：

```
符号主义（人手写规则）
   ↓ 死结：知识写不完，规则外就崩
心智社会（一群简单体协作）
   ↓ 死结：哲学讲通了，工程不知道怎么造
联结主义（神经网络学权重）
   ↓ 死结：会"看"，不会"做决定"
强化学习（试错中学策略）
   ↓ 死结：每个任务都要从零摸索，没常识
预训练大模型（海量文本自监督）
   ↓ 一次性补上：世界知识 + 通用推理
LLM 驱动的现代智能体
```

## 一、符号主义：智能 = 符号计算

这一派的理论底气来自 1976 年 **Newell 和 Simon** 提的**物理符号系统假说（PSSH）**，两个论断：

- **充分性**：任何物理符号系统，都**有本事**产生通用智能。
- **必要性**：任何表现出通用智能的系统，**本质上一定**是物理符号系统。

说白了就是一句话：**智能的本质是符号的计算与处理**。这个假说最厉害的地方不是内容，而是它把"人类心智是什么"这种哲学问题，变成了"怎么在计算机上实现"的工程问题——早期研究者因此信心爆棚。

### 两个代表作

**专家系统（以 MYCIN 为例）**

结构很简单：**知识库 + 推理机 + 用户界面**，核心思想是**知识与推理分离**。知识库用 `IF-THEN` 产生式规则存专家经验，推理机负责拿事实去匹配规则。

MYCIN（斯坦福，70 年代）诊断细菌性血液感染，约 **600 条规则**。这里有个我一直搞混的点，今天终于理清了——推理机的两种方向：

| | 正向链 | 反向链 |
|---|---|---|
| 起点 | 已知事实 | 一个假设的目标 |
| 驱动方式 | **数据驱动** | **目标驱动** |
| 通俗理解 | 有线索，往下推结论 | 有猜想，往回找证据 |

MYCIN 用的是**反向链**：从"确定致病菌"这个最高目标反推需要哪些证据，再去问医生。这也解释了为什么它的交互是一问一答式的——它在**倒着找证据**。

另一个创新是**置信因子 CF（-1 到 1）**，用来表示结论的可信度。医学诊断天生不确定，纯布尔逻辑不够用，这一点很关键。

**SHRDLU（Winograd，1968–1970）**

如果说专家系统是"深度"，SHRDLU 就是"广度"。它在一个**积木世界**（虚拟三维空间 + 机械臂）里用自然语言和人交互。让我惊讶的是它 1970 年就能做到：

- **指代消解**：`Find a block which is taller than the one you are holding...`，它知道 `the one you are holding` 指机械臂正抓的那个。
- **自主规划**：让它把蓝积木放到红积木上，红积木上已经有绿积木，它会自己规划出"先移开绿的"。
- **回答行为动机**：问"你为什么拿起红积木？"，它答 `BECAUSE YOU ASKED ME TO.`

它真正的历史地位是：**第一次把语言理解、规划、记忆这些独立模块集成进一个系统协同工作**，"感知-思考-行动"的闭环从这里开始。也就是昨天我跑的那个 Agent Loop 的思想源头，隔了五十多年。

### 但符号主义撞了四堵墙

这部分我觉得比前面的成就更重要，因为它解释了后面所有范式的动机：

1. **知识获取瓶颈**：知识要靠专家 + 知识工程师访谈、提炼、编码，成本高、慢、没法规模化。最要命的是，**专家自己的很多知识是内隐的、直觉性的，根本写不成 `IF-THEN`**。
2. **常识问题**："水是湿的""绳子能拉不能推"这种背景知识，没显式编码系统就一无所知。**Cyc 项目**手写了数十年常识，成果仍然很有限。
3. **框架问题**：动作执行后，怎么高效判断**哪些东西没变**？给每个动作声明所有不变状态，计算上不可行；而人类毫不费力就能忽略无关变化。这个反直觉的点我想了挺久——**"没变的部分"比"变了的部分"更难算**。
4. **系统脆弱性**：完全依赖预设规则，规则外的微小变化就可能整个失灵。SHRDLU 的成功恰恰是因为它活在一个规则完备的封闭世界里，真实世界全是例外。

## 二、ELIZA：亲手看清规则系统的天花板

2.2 节是动手环节，复现 1966 年 **Weizenbaum（MIT）** 的 ELIZA。最有名的脚本是 **DOCTOR**，模仿罗杰斯学派的非指导性心理治疗师。

它的机制其实"很水"：**从不正面回答问题，只识别关键词 → 套用转换规则 → 把你的陈述变成一个开放式提问**。

四步流程：

1. **关键词识别与排序**：每个关键词有优先级，命中多个就取优先级最高的规则。
2. **分解规则**：用通配符 `*` 捕获句子其余部分。规则 `* my *` 遇到 `"My mother is afraid of me"`，捕获 `["", "mother is afraid of me"]`。
3. **重组规则**：从关联的一组模板里**随机挑一条**（为了显得不那么机械），填入捕获内容。
4. **代词转换**：`I`→`you`、`my`→`your`，维持对话连贯。

教材给的 Python 实现不长，但有两个细节值得记：

```python
rules = {
    r'I need (.*)': ["Why do you need {0}?", ...],
    ...
    r'.*': ["Please tell me more.", ...]   # 兜底规则
}
```

- **`r'.*'` 必须放在字典最后**。因为 `respond()` 是按顺序 `re.search` 的，命中即返回；通配符要是放前面，后面的具体规则永远轮不到。
- **代词转换是按空格切词逐个查表**，查不到原样保留。所以它其实是纯字符串操作，没有任何"理解"。

跑起来的效果确实像那么回事：

```
You: I am feeling sad today.
Therapist: How long have you been feeling sad today?
You: My mother is not happy with my work.
Therapist: Tell me more about your mother.
```

### 三个致命局限

| 局限 | 具体表现 |
|------|---------|
| **缺乏语义理解** | 输入 `I am **not** happy`，它照样匹配 `I am (.*)` 生成"你这样多久了？"——完全不懂 `not` |
| **无上下文记忆** | 系统是**无状态的（Stateless）**，每次回应只看当前这一句，多轮对话根本连不起来 |
| **规则扩展性** | 加规则 → 规则库爆炸 → 冲突和优先级管理失控 → 不可维护 |

这里让我最有触动的是 Weizenbaum 的**真实意图**：他压根不是想造出能"理解"情感的程序，恰恰相反，**他想证明简单的句式转换就能在完全不理解内容的情况下制造出"智能"和"共情"的假象**。结果适得其反——很多人（包括他的秘书）真的对它产生了情感依赖。这就是著名的 **ELIZA 效应**。

对照昨天跑的 Agent，区别一下子就清楚了：ELIZA 的"聪明"是设计者写死的，Agent 的决策是 LLM 当场推理出来的。**前者在表演理解，后者至少在做推理。**

## 三、明斯基的《心智社会》：智能是"涌现"出来的

符号主义走进死胡同之后，**Minsky** 在 1986 年的《心智社会》里没有继续给中央推理机加规则，而是换了个问法。他那句话我抄下来了：

> "What magical trick makes us intelligent? The trick is that there is no trick. The power of intelligence stems from our vast diversity, not from any single, perfect principle."

**没有魔法把戏。智能的力量来自巨大的多样性，而不是某个单一完美的原则。**

他的三个核心概念：

- **智能体（Agent）**：注意，这里指的是**极其简单、专门化、自身"无心"**的心智过程，比如 `LINE-FINDER`、`GRASP`。这和昨天学的那个能推理的现代智能体**完全不是一个东西**，我一开始就被这个术语坑了。
- **机构（Agency）**：一组协同工作的智能体，比如 `BUILD` 由 `SEE`/`FIND`/`GET`/`PUT` 组成，彼此靠**去中心化的激活与抑制信号**影响。
- **涌现（Emergence）**：复杂的智能行为**不是**某个高级智能体规划的，而是从大量简单单元的**局部交互**中自发产生的。

"搭积木塔"那个例子特别直观：

```
"我要搭一个塔"
  └─ BUILD-TOWER   ← 不知道怎么执行物理动作，只负责激活下属
       └─ BUILDER       ← 只有一个循环：塔没搭完就激活 ADD-BLOCK
            └─ ADD-BLOCK     ← 依次协调 FIND-BLOCK / GET-BLOCK / PUT-ON-TOP
                 └─ GET-BLOCK     ← 激活 SEE-SHAPE、REACH、GRASP
```

关键在于：**链条上没有任何一环拥有全局规划**。`GRASP` 只管抓握，不知道什么是塔；`BUILDER` 只管循环，不知道怎么控制手臂。但整群"无心"的简单体按激活/抑制规则互动起来，"搭塔"这个看起来很智能的行为就自然涌现了。

### 它为什么重要

这个理论直接催生了**分布式人工智能（DAI）**和**多智能体系统（MAS）**，三点启发：

| 启发 | 后来变成了什么 |
|------|--------------|
| **去中心化控制** | MAS 的核心课题：没有中心节点时怎么协调和分配任务 |
| **涌现式计算** | 蚁群算法、粒子群优化 |
| **智能体的社会性** | 通信语言（ACL）、交互协议（契约网）、协商策略、信任模型 |

它提出的那个大问题也很有启发：如果一个心智内部的智能是协作涌现的，那**多个物理上分离的计算实体之间，是不是也能涌现出更强的"群体智能"**？研究焦点从此从"造一个全能的单体"转向"设计一个会协作的群体"。

## 四、学习范式三连跳

心智社会在哲学上指了路，但没给工程方法。于是问题变成：**如果智能没法被完全设计出来，那它能不能被"学"出来？**

### 第一跳：联结主义（80 年代复兴）

和符号主义"自上而下写规则"相反，它是**自下而上**模仿大脑神经网络。三条核心：

1. **知识的分布式表示**：知识不存在某个知识库里，而是以**连接权重**的形式分散在大量神经元的连接之间。**整个网络的连接模式本身就是知识。**
2. **简单的处理单元**：每个神经元只做"加权输入 → 激活函数 → 输出"。
3. **通过学习调整权重**：智能不来自预写的程序，而来自接触大量样本后按**反向传播**等算法迭代调整权重。

我觉得这一节最该记住的是那句对比：**符号主义是把人类的知识显式编码给机器，联结主义是造一个能像人类一样自己学会知识的机器。**

不过它主要解决**感知**（"图里有什么"），解决不了**决策**（"这情况我该干什么"）。

### 第二跳：强化学习（RL）

专门解决**序贯决策**。以 **AlphaGo（Silver et al., Nature 2016）** 为例，它的自我对弈完全自主，**不依赖人类棋谱的直接指导**。

五要素：

| 要素 | AlphaGo 里对应什么 |
|------|-------------------|
| 智能体 Agent | 决策程序 |
| 环境 Environment | 围棋规则和对手 |
| 状态 State | 棋盘上所有棋子的位置 |
| 行动 Action | 在合法位置落子 |
| 奖励 Reward | 胜 +1 / 负 -1 |

交互闭环：观察 $S_t$ → 按**策略 π**（状态到行动的映射）选 $A_t$ → 环境转移到 $S_{t+1}$ → 反馈 $R_{t+1}$ → 用这个反馈更新策略，**这个更新过程就是学习**。

这里有个我原本理解错的点：RL 的目标**不是**最大化即时奖励，而是最大化未来的**累积奖励（回报 Return）**。所以智能体必须有"远见"，围棋里的"弃子"就是主动牺牲眼前利益换长期收益。

但 RL 的短板也很明显：需要海量任务专属的交互数据，而且**开局没有任何先验常识**，一切从零摸索。

### 第三跳：大规模预训练

问题变成：**怎么让智能体在学具体任务之前，就先具备对世界的广泛理解？**

答案是 **预训练-微调（Pre-training, Fine-tuning）** 两步：

1. **预训练**：在互联网级海量文本上用**自监督学习**训练超大模型。目标不是完成任何特定任务，而是学语言本身的规律、语法、事实知识和上下文逻辑。最常见的目标就是**"预测下一个词"**。
2. **微调**：针对下游任务，只需**少量标注数据**就能适应。

这一步的意义，我现在才真正体会到：**数万亿文本训练出来的权重，实际上是一个关于世界知识的、高度压缩的隐式模型**。它用一种全新的方式解决了符号主义时代那个最棘手的"知识获取瓶颈"——不用再让人一条条写规则了，知识是从数据里自己压出来的。

更意外的是**涌现能力**：模型规模（参数量、数据量、计算量）跨过某个阈值后，出现了没被直接训练过的能力：

- **上下文学习（In-context Learning）**：不改权重，只在输入里给几个示例（Few-shot）甚至不给示例（Zero-shot），就能完成新任务。
- **思维链（Chain-of-Thought）**：让模型先输出一步步推理过程，逻辑、算术、常识推理的准确率显著提升。

到这一步，LLM 已经不只是语言模型了，它同时是**海量知识库**和**通用推理引擎**。

> 注意这里"涌现"这个词第二次出现了。心智社会的涌现是"简单体局部交互产生复杂行为"，LLM 的涌现是"规模跨阈值产生新能力"——名字一样，机制完全不同，别混。

## 五、终点：LLM 智能体闭环，与三大思潮的合流

图 2.10 那个架构，其实就是昨天我跑的那个循环的完整版：

| 阶段 | 涉及模块 | 干什么 |
|------|---------|-------|
| **感知 Perception** | 感知模块 | 从外部环境接收输入形成**观察**（用户指令、API 返回、状态变化） |
| **思考 Thought** | 规划模块 + LLM + 记忆模块 | 规划模块靠**反思**和**自我批判**把宏观目标拆成可执行步骤；LLM 结合历史信息推理，决策出下一步，通常是一次**工具调用** |
| **行动 Action** | 执行模块 + 工具箱 | 解析指令，从工具箱里挑合适的工具（代码执行器、搜索、API）去和环境交互 |
| **观察 Observation** | 感知模块 + 记忆 | 工具返回**结果**，环境状态改变，两者合成新一轮观察；同时**更新记忆**，进入下一轮 |

而回头看整章，现代智能体其实是**三大思潮的合流**：

| 思潮 | 代表 | 主张 | 成果 |
|------|------|------|------|
| **符号主义** | Simon、Minsky | 智能 = 符号操作 + 逻辑推理 | SHRDLU、专家系统、深蓝 |
| **联结主义** | Hinton | 模仿神经网络；反向传播奠基 | CNN、Transformer |
| **行为主义** | —（现代化身是 RL） | 在环境互动与试错中学策略 | TD-Gammon、AlphaGo |

最妙的是这个结论：**GPT 这类大模型本身是联结主义的产物，却在充当执行符号推理、工具调用和规划决策的"大脑"**——形成了**神经-符号结合**的现代智能体架构。七十年三个流派，最后拼成了一个东西。

（另外教材提到那张 AI Agent 技术栈全景图是 **Letta 公司 2024 年 11 月**发布的，可以拿来了解当前的生态格局。）

## 六、习题作答（共 7 题）

> 正文写于 2026-09-16，本节习题于 2026-09-17 补做。第 3 题是动手题，实际编写并运行了扩展代码。

### 习题 1：物理符号系统假说

**两个论断的含义**

- **充分性**：任何物理符号系统都**具备产生通用智能行为的充分手段**——有它就够了。
- **必要性**：任何展现通用智能行为的系统，其**本质必然是**物理符号系统——没它不行。

合起来就是一句话：智能的本质是符号的计算与处理。

**哪些问题挑战了"充分性"**

本章提到的四个根本挑战，全都是冲着充分性去的：

| 挑战 | 为什么动摇充分性 |
|------|----------------|
| 知识获取瓶颈 | 专家的很多知识是**内隐的、直觉性的**，写不成 `IF-THEN`。充分性的前提是知识能被完整符号化，而这个前提本身不成立 |
| 常识问题 | Cyc 手写数十年常识仍成果有限——说明"把世界符号化"这条路在工程上走不通 |
| 框架问题 | 无法穷举动作后**哪些状态没变**，符号推理在动态世界里计算上不可行 |
| 系统脆弱性 | 规则外的微小变化即失灵。SHRDLU 的成功恰恰依赖封闭世界 |

我的理解是：这四点**没有在逻辑上证伪充分性**，而是证明了它在实践中不可达——"理论上做得到"和"人类做得到"之间隔着一道无法跨越的工程鸿沟。

**LLM 智能体是否符合 PSSH？**

这题我想了一会儿，觉得不能简单回答是或否，得看**在哪个层面看**：

- **从内部表示看：不符合。** LLM 的知识存在数十亿个连续浮点权重里，不是可区分的离散符号结构，操作也不是符号演算而是矩阵乘法。
- **从系统边界看：符合。** 智能体对外的行为层——提示词、工具调用的 JSON、ReAct 的 `Thought/Action/Observation` 文本、返回给用户的结论——**全都是实打实的符号操作**。

所以我的判断是：**LLM 智能体没有推翻 PSSH，而是把符号系统从"内核"降级成了"接口和骨架"。**

更有意思的是两个论断的命运似乎反过来了：

- **必要性论断被部分证伪**——智能的内核确实是连续的向量运算，不是离散符号处理。
- **充分性论断反倒以曲折的方式成立了**——符号层（工具、结构化输出、显式规划）确实是现代智能体不可或缺的组成部分，纯神经网络不接工具是做不成 Agent 的。

这也正是教材说的"神经-符号结合"。

### 习题 2：MYCIN 为什么没能进临床

**除了知识获取瓶颈和脆弱性，还有哪些阻碍**

教材只讲了技术层面，我觉得**非技术因素可能才是决定性的**：

1. **法律责任主体不明**。误诊了谁负责——医生、开发者、还是医院？70-80 年代根本没有软件医疗责任框架，也没人敢当第一个用的人。
2. **无法构成知情同意**。CF 是个 -1 到 1 的数值，医生看不懂它怎么来的，患者更不可能基于它做治疗决定。
3. **知识时效性 + 没人付维护费**。约 600 条规则是 70 年代的医学知识，而抗生素耐药性每年都在变。**规则库需要持续维护，但没有任何商业模式支撑这件事**——这一点我觉得最致命，技术再好也养不活。
4. **集成成本**。MYCIN 是独立的问答系统，要接入医院的化验单和病历系统，接口工作量巨大，而当时医院连电子病历都还没普及。
5. **临床流程负担**。反向链是一问一答式的（它在倒着找证据），这对本来就繁忙的医生来说是额外负担，不是减负。
6. **专业自主权**。医生不接受被机器指导，尤其在诊断这种高度依赖经验和权威感的领域。
7. **监管路径缺失**。当时 FDA 还没有软件医疗器械的审批通道。

**如果现在设计一个医疗诊断智能体**

我的思路是：**MYCIN 的核心局限不是"规则不够多"，而是知识无法自主更新 + 无法处理规则外的情况**。所以设计要针对这两点：

- **不让 LLM 直接当诊断结论出口**，只当信息整合与鉴别诊断辅助。
- **RAG 挂载权威知识库**（临床指南、UpToDate、药典），**每条结论强制带引用可溯源**——把 MYCIN 时代丢失的可解释性找回来一部分。
- **人在环路**：智能体只输出候选鉴别诊断 + 支持证据 + 校准后的置信度，**最终判断权归医生**，并记录医生的采纳/否决。
- **工具调用**：查药物相互作用、查最新指南、调影像模型、算剂量。
- **不确定性显式建模**：继承 MYCIN 的 CF 思想，但升级为校准概率，并且**必须学会说"证据不足，建议进一步检查"**——这是 MYCIN 做不到的。
- **全链路审计日志**：每一步 `Thought/Action/Observation` 留痕，满足医疗合规。
- **分层权限 + 红队测试**：高风险动作（开处方）二次确认。

**哪些领域规则系统至今仍然更好**

判断标准我想清楚了，就一句话：**当"必须能解释为什么"比"准确率再高 2%"更重要时，规则系统胜出。**

具体场景（共同特征是：规则空间封闭 + 后果严重 + 需要 100% 可审计 + 数据稀缺）：

| 领域 | 为什么规则系统更好 |
|------|-----------------|
| 航空航天 / 核电安全联锁 | DO-178C、IEC 61508 要求形式化验证，**神经网络目前无法通过适航认证** |
| 税务计算 / 财务合规审计 | 税法本身就是明确条文，客户和监管要求能追溯到具体条款 |
| 药物剂量上限校验、设备报警阈值 | 宁可误报不可漏报，规则的行为完全可预测 |
| 反洗钱规则引擎 | 监管要求解释每一笔拦截的依据 |
| 工业安全联锁、消防规范审查 | 后果不可逆，容不得概率性判断 |

这也解释了为什么静态分析工具（Lint、SonarQube）到今天还活得好好的——习题 7 会再遇到它。

**（4）跑完之后发现的四个真实缺陷**

这部分是看代码看不出来的，**只有跑起来才看得见**：

1. **标点污染 bug**：`exhausted.?` 这种 `.?` 满天飞。因为 `{0}` 把句尾的 `.` 一起捕获进来了。小事，但暴露了它是纯字符串操作。
2. **因果理解为零**：我说"The deadline keeps moving and I am exhausted"，它只抓后半句，问"你这样多久了"——**完全没意识到"deadline 一直变"才是原因**。它匹配到了词，但词与词之间的关系对它不存在。
3. **记忆是随机抽槽位，不是相关的**：聊网球的时候，它翻出来的是"你 24 岁"。**记住了 ≠ 会用**。真正的记忆需要判断"当前话题和哪条记忆相关"，而这需要语义理解——恰恰是它没有的东西。
4. **规则顺序是一份隐式契约**：`I am not` 必须排在 `I am (.*)` 前面，否则否定句会被吞掉。这个顺序**没有任何机制保证，全靠开发者自觉**。我这次加 6 条就得手动排一次序。

第 4 点是理解"组合爆炸"的钥匙，下面单独说。

**（5）与 ChatGPT 的本质差异**

| 维度 | 扩展版 ELIZA | ChatGPT |
|------|-------------|---------|
| **知识来源** | 我手写的 6 类规则、约 40 条模板 | 数万亿 token 预训练的分布式权重 |
| **语义理解** | **零**。正则匹配字符串，不懂 `not`、不懂因果 | 能理解否定、反讽、隐含因果 |
| **上下文** | 4 个槽位 + 复读上一句，**随机抽取** | 长上下文窗口，跨几十轮保持一致并选择性引用 |
| **泛化能力** | 只能覆盖我预先想到的句式，未覆盖即落入兜底 | 未见过的表述也能合理回应 |
| **回应生成** | 从有限模板挑一个填空 | 逐 token 生成，回应空间实质无限 |
| **可解释性** | **100% 可追溯**，能指出命中哪条规则 | 权重不可读，只能事后归因 |

最后一行值得划重点：**可解释性是扩展版 ELIZA 唯一胜过 ChatGPT 的维度**。这条线会一路贯穿习题 1、2、6、7。

**（6）组合爆炸的数学说明**

设词汇量 $V$，句长上限 $n$，可能的句子数：

$$|S| = \sum_{i=1}^{n} V^{i} \approx V^{n}$$

取常用英文词 $V = 5\times10^{4}$、$n = 15$，则 $|S| \approx 10^{70}$ 量级——**远超可穷举范围**。

但真正的杀手不是句子数，而是这两层叠加：

**第一层：规则数随语言复杂度指数增长。** 规则要覆盖的是**语义等价类**而非字面句子，设等价类数为 $K$，则需规则数 $R \geq K$。而 $K$ 随「话题数 × 意图数 × 实体类型数」组合增长，仍是指数级。

**第二层：冲突维护成本随规则数平方增长。** $R$ 条规则两两可能冲突，需检查

$$\binom{R}{2} = \frac{R(R-1)}{2} = O(R^{2})$$

我这次只加了 6 条，就得手动确认 `I am not` 排在 `I am` 前面。**规则到几百条时，这个人工排序完全不可维护**——而且冲突不只是顺序问题，还有语义重叠、优先级反转、通配符吞并。

**双重爆炸：规则数指数增长 × 冲突检查平方增长。** 这就是为什么 Cyc 手写数十年常识仍然成果有限，也是为什么"再加一条规则"这个补丁思路注定失败。

### 习题 4：心智社会 vs 现代多智能体系统

**`GRASP` 失效会发生什么**

关键在于链条上**没有任何一环拥有全局规划**，所以失效会一路"哑"上去：

1. `GET-BLOCK` 激活 `GRASP`，拿不到结果。
2. `ADD-BLOCK` 卡在 `GET-BLOCK`，等不到完成信号。
3. `BUILDER` 的循环条件"塔还没搭完"仍为真，于是**再次激活 `ADD-BLOCK`**——如果 `GRASP` 是硬失效，这里就是**死循环**。
4. `BUILD-TOWER` 完全不知道下面出事了，因为它只负责激活下属。

**结果是系统卡死或空转，而且没有任何模块能报告"为什么"**——因为没有模块持有全局视图，也就没有模块有资格做出"抓握能力缺失"这个判断。

**去中心化架构的优劣**

| | 优势 | 劣势 |
|---|------|------|
| 鲁棒性 | 单点失效不至于全盘崩溃，其他智能体可继续工作（但前提是失效可被绕过） | 失效**难以被检测和定位**，如上例的死循环 |
| 可扩展性 | 加智能体不需要改中央控制器 | 加得越多，交互组合越复杂 |
| 灵活性 | 局部交互可产生计划外的解决方案（涌现） | **无法保证全局最优**，也无法保证收敛 |
| 调试 | — | **极难调试**：没有中心日志，行为是交互产物，不可复现推理链 |
| 可解释性 | — | 涌现行为没有明确责任主体，"谁决定这么做的"无法回答 |

**这个劣势我在昨天跑 Agent 时其实已经撞过一次**：多轮工具调用失败时，如果框架没有把错误往上传，Agent 就会反复重试同一个动作。心智社会理论描述的正是这种失效模式的根源——**去中心化天然缺乏全局错误归因能力**。

**与 CAMEL-Workforce / MetaGPT / CrewAI 的对比**

| | 心智社会 | 现代 MAS |
|---|---------|---------|
| 智能体粒度 | 极简、"无心"的原子过程（`GRASP`、`LINE-FINDER`） | **本身就是 LLM 驱动的完整智能体**，各自具备推理能力 |
| 数量级 | 成千上万个 | 通常 2-10 个 |
| 协作机制 | 激活/抑制信号，隐式 | 自然语言消息 + 显式协议（角色分配、任务队列） |
| 是否涌现 | **完全涌现**，无全局规划 | **半涌现**：有编排层（Orchestrator）做任务分解和调度 |
| 角色定义 | 无角色概念 | 明确角色（产品经理、工程师、测试） |

**关联**：去中心化协作、群体智能、局部交互产生整体能力，这三个思想被完整继承。

**本质不同**（我认为是这两点）：

1. **现代 MAS 是"少而强"，心智社会是"多而弱"。** MetaGPT 里一个"工程师 Agent"本身就是个完整 LLM 智能体，它的内部能力**不是涌现出来的，而是预训练给的**。涌现只发生在 Agent 之间的协作层，不发生在单个 Agent 内部。
2. **现代 MAS 普遍重新引入了中心化编排。** CrewAI 有 Process 类型（sequential/hierarchical），CAMEL-Workforce 有协调者。这恰恰是因为纯去中心化在工程上**难以保证收敛和可调试性**——上面那个 `GRASP` 死循环的问题，现实系统必须有人兜底。

所以我的看法是：**现代 MAS 是心智社会在"智能体单元强度"这个维度上的放大，同时在"控制结构"这个维度上的收缩。** 单元变强了，于是不需要那么多；不需要那么多，于是可以重新中心化。

**心智社会在 LLM 时代还适用吗**

我倾向于认为：**理论内核仍然适用，但适用层面发生了迁移。**

Minsky 说智能体可以是"无心"的简单过程，而今天的 LLM 明显有强推理能力。表面看是矛盾的。但拆开看：

- **LLM 内部仍然是"无心单元"的社会。** Transformer 里每个注意力头、每个神经元都只做极简单的加权运算，没有任何一个"懂语言"。理解能力是数十亿个简单单元交互的涌现结果。**这正是心智社会的精确描述**——只不过单元从 `GRASP` 换成了神经元和注意力头。
- **多智能体系统层同样适用。** Agent 之间的协作涌现，和明斯基的机构层级是同构的。

所以不是理论失效了，而是**涌现发生的尺度变了**：1986 年明斯基把涌现放在"心智过程"这一层，今天涌现主要发生在"神经元权重"这一层（LLM 内部）和"Agent 协作"这一层（MAS）。中间那一层——他设想的 `GRASP`、`BUILD-TOWER` 这种符号化的简单过程——确实被神经网络吃掉了。

顺带一个对照：教材里"涌现"出现了两次，**心智社会的涌现是"简单体局部交互产生复杂行为"，LLM 的涌现是"规模跨阈值产生新能力"**，机制完全不同。但两者在哲学上共享同一个信念：**整体大于部分之和，且无法从部分预测**。这大概就是 Minsky 那句"The trick is that there is no trick"的真正意思。

### 习题 5：强化学习 vs 监督学习

**用 AlphaGo 说明试错学习**

五要素映射到围棋：智能体=决策程序，环境=棋盘规则和对手，状态=当前棋局布局，行动=在合法位置落子，奖励=胜 +1 / 负 -1。

一轮循环：观察 $S_t$（棋盘）→ 按策略 $\pi$ 选 $A_t$（落子）→ 环境转移到 $S_{t+1}$ → 反馈 $R_{t+1}$ → 用反馈更新 $\pi$。

**试错机制的核心是"奖励极度稀疏且延迟"**：一整局棋几百手，但胜负信号只在最后一刻给出。中间每一步落子的好坏，都得靠**价值函数沿时间步回溯**来评估。AlphaGo 通过数百万次自我对弈积累这些轨迹，逐渐学会"什么棋局下什么子更可能通向胜利"——**完全不依赖人类棋谱**。

这也解释了为什么它能下出人类从未见过的棋：它不是模仿，而是在奖励信号引导下自己探索出了策略空间。

**为什么 RL 特别适合序贯决策**

序贯决策的定义特征是：**当前选择会改变未来可选的状态空间**。围棋里现在占角，以后就没这个角了。

监督学习处理的是独立的 $(x, y)$ 样本对——**每个样本互不影响**。而序贯决策里，样本之间是有因果链的，$A_t$ 直接决定了 $S_{t+1}$。RL 的目标函数是最大化**累积回报**而非单步准确，天然把"当前动作影响未来"编码进了数学形式里。围棋的"弃子"就是典型：牺牲 $R_t$ 换取更大的 $\sum R$。

**数据需求的本质区别**

| | 监督学习 | 强化学习 |
|---|---------|---------|
| 数据来源 | 人工标注的 $(x, y)$ 对 | 智能体自己与环境交互产生 |
| 标签成本 | **高**，需要专家标注 | 只需要一个奖励函数 |
| 数据上限 | 受标注预算限制 | 理论上无限（只要能交互） |
| 能否超越人类 | **不能**，天花板是标注者水平 | **能**，可探索出人类未知策略 |
| 反馈形式 | 密集、即时、明确 | 稀疏、延迟、常为标量 |

最后一行是 RL 的代价：**奖励稀疏 + 延迟，导致样本效率极低**，需要海量交互。这是 AlphaGo 要烧那么多算力的根本原因。

**训练超级马里奥智能体**

- **监督学习需要**：大量「游戏画面 → 人类高手操作」的配对数据。得录像高水平玩家的每一帧和对应按键。
- **强化学习需要**：一个奖励函数（前进距离 +、吃金币 +、死亡 −−、通关 ++）+ 模拟器环境。**不需要任何人类演示**。

**RL 明显更合适**，理由有四：

1. **数据可得性**：马里奥有模拟器，可以让智能体 24 小时无成本重试，而高质量人类录像很难批量采集和标注。
2. **操作精度**：跳跃时机是帧级连续决策，人类标注很难精确到帧。
3. **可超越人类**：RL 能发现非常规路线（穿墙、卡 bug 速通），监督学习只能复刻标注者的水平。
4. **序贯性强**：这一跳决定下一段的落脚点，是典型的序贯决策问题。

不过实际工程中常用**混合方案**：先用少量人类演示做模仿学习（behavior cloning）冷启动，再用 RL 微调。因为纯 RL 从零开始，**连"往前走"都要试很久**——这恰好是习题 3 里 RL 的短板：缺乏先验知识。

**RL 在 LLM 训练中的关键作用**

预训练（自监督）之后，RLHF / DPO 用人类偏好数据做强化学习对齐。它解决的是预训练**解决不了**的问题：

- 预训练的目标是"预测下一个词"，学到的是**人类语料的分布**——包括有害内容、错误信息、啰嗦冗余。
- 它**不知道什么是"好回答"**。一个模型可以完美预测下一个词，却答非所问。

RL 在这里补的是**价值对齐**：把"人类更偏好哪个回答"变成奖励信号，让模型学会不只是"像人类说话"，而是"给出有用、安全、符合意图的回答"。

这一步在智能体场景里更关键，因为 Agent 需要**多轮决策**——什么时候调工具、什么时候停、失败了怎么重试。这些全是序贯决策，正是 RL 的主场。

### 习题 6：预训练-微调范式

**为什么说预训练解决了知识获取瓶颈**

符号主义的瓶颈在于：**知识必须由人类专家一条条写出来，而很多知识是内隐的、写不出来的**。

预训练的破法是把获取方式整个反过来：**不让人写，让模型从海量文本里自己压出来**。数万亿 token 的语料本身就承载了人类积累的事实、常识、逻辑关系，自监督的"预测下一个词"任务迫使模型把这些结构编码进权重。

**知识表示方式的本质区别**

| | 符号主义 | 预训练 |
|---|---------|-------|
| 表示形式 | 显式离散符号 + `IF-THEN` 规则 | 连续浮点数权重，**分布式表示** |
| 可读性 | **完全可读**，人能逐条审查 | **完全不可读**，数十亿参数无从解读 |
| 可编辑性 | 可精确增删改一条规则 | 几乎无法定向修改某条知识 |
| 泛化性 | 差，规则外即失效 | 强，能处理未见过的表述 |
| 获取成本 | 极高，靠专家手工 | 一次性算力投入，之后边际成本低 |
| 知识来源 | 单个专家的领域知识 | 全人类公开文本 |
| 鲁棒性 | 脆弱 | 相对鲁棒 |

**这是一次交换，不是单纯的进步**：符号主义用可解释性和可编辑性换了鲁棒性和规模化。习题 2 里那些至今用规则系统的领域，正是**宁可要可解释性也不要鲁棒性**的场景。

**互联网数据带来的问题**

1. **偏见与歧视**：语料反映社会现实，模型会复制并放大性别、种族、地域偏见。
2. **事实性错误与幻觉**：互联网本身充满错误信息，且模型无法区分权威来源和谣言。权重是**有损压缩**，细节会失真。
3. **时效性**：训练数据有截止日期，之后的事件一无所知。
4. **版权与合规**：大量语料未经授权抓取，涉及作者权益。
5. **隐私泄露**：训练数据里的个人信息可能被记忆并在输出中复现。
6. **数据污染与模型坍缩**：互联网上 AI 生成内容越来越多，未来训练数据可能被污染，导致质量退化。
7. **知识分布不均**：英文语料远多于其他语言，导致非英语世界被系统性低估。

**缓解手段**

| 问题 | 手段 |
|------|------|
| 偏见 | 数据去偏、宪法式 AI（RLAIF）、红队测试 |
| 幻觉 | RAG 挂载可信知识库 + 强制引用溯源、事实校验器 |
| 时效性 | RAG、工具调用实时检索、持续预训练 |
| 版权 | 数据授权、来源过滤、opt-out 机制 |
| 隐私 | 数据脱敏、差分隐私、机器遗忘（machine unlearning） |
| 污染 | 数据来源溯源、质量分层、人工抽检 |
| 分布不均 | 多语言语料扩充、跨语言迁移 |

我的观察是：**RAG 和工具调用其实是在把符号主义时代的"外挂知识库"请回来**——权重负责通用推理，外部知识库负责可溯源的事实。这又是神经-符号结合的一个体现。

**预训练-微调会被取代吗**

我倾向于认为：**微调这一步正在被削弱，但预训练本身在可预见的未来不可替代。**

- **正在被削弱的**：全参数微调。因为上下文学习（In-context Learning）和思维链让很多任务**无需改权重**就能完成——给几个示例即可。这直接侵蚀了"微调"的必要性。LoRA 等参数高效方法也在把微调成本压到极低，进一步弱化"为每个任务单独训一个模型"的做法。
- **不可替代的**：预训练。因为它是**知识获取的唯一规模化手段**。除非出现全新的知识注入方式，否则任何模型都得先从数据里学世界知识。
- **可能的演进方向**：从"预训练 + 微调"转向"预训练 + 推理时适应"（test-time adaptation）——模型不改权重，而是在推理时通过长上下文、检索、自我反思来临时适配任务。Agent 框架本质上就是这条路。

所以我的判断：**范式会演化，但"先从海量数据学通用能力"这个内核不会变**。它太成功地解决了知识获取瓶颈，目前没有别的方案能替代。

### 习题 7：三个时代设计代码审查助手

这题最能检验整章理解，我认真写了三版方案。

**（1）符号主义时代（1980 年代）**

**实现方式**：专家系统架构 = 知识库 + 推理机。

- 知识库：人工编码代码规范，如
  - `IF 函数长度 > 100 行 THEN 警告"函数过长"`
  - `IF 变量未初始化 AND 被读取 THEN 错误"可能使用未定义值"`
  - `IF malloc 调用 AND 无对应 free THEN 警告"内存泄漏风险"`
- 推理机：反向链，从"这段代码有问题吗"这个目标反推需要检查哪些条件。
- 输入：AST（抽象语法树）——符号化的代码结构表示。

**会遇到的困难**：

1. **"实现逻辑概括"根本做不到。** 理解代码意图需要语义理解，而规则只能匹配语法模式。这一项在那个时代是**不可能任务**。
2. **规则爆炸。** 编程语言 × 框架 × 编码风格 × 业务领域，组合数天文数字。正是习题 3 里的双重爆炸。
3. **误报率极高。** 规则无法理解上下文，一个刻意为之的写法会被判成 bug，开发者很快就会忽略所有警告——**工具直接失效**。
4. **框架问题。** 改一行代码会影响哪些地方？静态分析无法穷举。
5. **无法处理新范式。** 遇到规则库没覆盖的写法就完全失灵（系统脆弱性）。

**现实对照**：这一版方案**并非假设，它真实存在**——就是 Lint 和 SonarQube。而它们至今仍在被使用，原因正是习题 2 里那条判断标准：**规则可解释、可审计、行为完全可预测**。所以符号主义方案没死，只是退守到了"确定性检查"这个它擅长的窄领域。

**（2）深度学习时代（2015 年左右，无 LLM）**

**实现方式**：

- **代码表示学习**：Code2Vec / Code2Seq，把 AST 路径编码成向量。
- **缺陷分类**：训练二分类器判断"这段代码有 bug 吗"，用历史 bug 库做监督学习。
- **序列模型**：LSTM / seq2seq 做代码摘要（自动生成函数注释）。
- **异常检测**：学习正常代码模式，偏离即报警。

**相比 1980 年代的进步**：

- 不用手写规则了，**知识从数据里学**（联结主义的优势）。
- 能捕捉统计模式，对未见过的写法有一定泛化能力。
- 代码摘要第一次变得**勉强可行**。

**仍然的困难**：

1. **需要大量标注数据**：哪段代码有 bug 需要人工标注，成本极高且标注质量参差。
2. **只能分类，不能解释**：模型说"这段有问题"，但**说不出为什么**、也**给不出改进建议**。而这是任务的核心要求。
3. **上下文窗口极短**：LSTM 处理几百行就衰减，无法理解跨文件依赖。
4. **无推理能力**：无法做多步逻辑分析，比如"这个并发访问在什么条件下会死锁"。
5. **无法交互**：不能追问、不能根据项目约定调整标准。

这一版的天花板是：**从"几乎不可能"进步到了"能打分，但不能说人话"**。

**（3）当前 LLM 智能体时代**

参照图 2.10 的架构，我会这样设计：

| 模块 | 职责 |
|------|------|
| **感知模块** | 接收 PR 的 diff、变更文件全文、关联的 issue/需求描述、项目 README 和编码规范、CI 测试结果 |
| **记忆模块** | 短期：本次审查的上下文窗口；长期：项目的历史审查记录、团队约定、过去被否决的建议（避免重复提同样的意见） |
| **规划模块** | 把"审查这个 PR"分解为：① 理解变更意图 → ② 逐文件分析 → ③ 检查跨文件影响 → ④ 运行工具验证 → ⑤ 汇总建议；并通过**反思和自我批判**过滤掉低质量发现 |
| **LLM（中枢）** | 理解代码语义、概括实现逻辑、推理潜在 bug、生成自然语言建议 |
| **工具箱** | **静态分析器**（SonarQube/Lint，拿确定性结论）、**测试执行**（跑单测验证假设）、**类型检查器**、**依赖分析**、**代码搜索**（找相似实现）、**Git blame**（查历史） |
| **执行模块** | 调用工具、解析结果、把发现写成 PR 评论、按严重级别排序 |

**闭环流程**：感知 diff → 规划分解 → LLM 推理出可疑点 → **调用静态分析器或跑测试验证** → 观察结果 → 反思过滤误报 → 生成带证据的建议 → 提交评论。

关键设计是**"先验证再报告"**：LLM 的怀疑必须经过工具验证才输出，这是压制幻觉的核心手段。

**（4）三个时代对比：从"几乎不可能"到"可行"**

| 能力 | 1980s 规则系统 | 2015 深度学习 | 当前 LLM 智能体 |
|------|--------------|-------------|---------------|
| 语法层检查 | ✅ 擅长 | ✅ 可以 | ✅ 可以 |
| 理解代码意图 | ❌ 不可能 | ⚠️ 勉强（摘要） | ✅ 可以 |
| 概括实现逻辑 | ❌ | ⚠️ 生成注释级别 | ✅ 自然语言解释 |
| 发现潜在 bug | ⚠️ 仅已知模式 | ✅ 统计分类 | ✅ 可推理未知模式 |
| **解释为什么** | ✅ 能指规则 | ❌ 黑箱 | ✅ 能说理 |
| **给改进建议** | ❌ | ❌ | ✅ |
| 跨文件理解 | ❌ | ❌ | ✅ 长上下文 |
| 泛化到新写法 | ❌ 脆弱 | ⚠️ 有限 | ✅ 强 |
| 误报控制 | ❌ 极高 | ⚠️ | ✅ 工具验证 + 反思 |
| 可交互追问 | ❌ | ❌ | ✅ |

**演进如何使任务变得可行——三个关键跃迁**：

1. **知识获取方式（符号 → 联结）**：不再需要人工穷举所有代码规范，模型从海量开源代码里自己学会了"什么是好代码"。这解决的是**规则爆炸**。
2. **决策与推理能力（+ RL / 思维链）**：从"匹配模式"升级为"多步推理"，能分析"这个锁在这个调用路径下会不会死锁"。这解决的是**语义理解**。
3. **知识与推理的合一（预训练）+ 工具调用（智能体架构）**：LLM 同时是知识库和推理引擎，而工具箱补上了确定性验证。这解决的是**误报率**——也正是符号主义唯一真正的优势（可验证）被重新引入。

**最深的一层体会**：现代方案不是替代了前两个时代，而是**把它们都吸收进来了**。静态分析器还在工具箱里（符号主义），代码表示学习是 LLM 的基础（联结主义），反思和自我批判机制带着试错的味道（行为主义）。**习题 1 里那个"神经-符号结合"的结论，在这道题上体现得最具体。**
