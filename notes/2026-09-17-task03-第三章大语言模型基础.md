## 一、语言模型在算什么：从数数到向量

### N-gram：把不可能的问题砍成可能的问题

语言模型的根本任务就一句话：**计算一个词序列出现的概率**，也就是判断什么句子是通顺的。

理论上用链式法则展开：

$$P(S)=P(w_1)\cdot P(w_2|w_1)\cdot P(w_3|w_1,w_2)\cdots P(w_m|w_1,\dots,w_{m-1})$$

但这个公式**根本算不了**——$P(w_m|w_1,\dots,w_{m-1})$ 要求统计"前面这么长一串词之后接这个词"的频率，而这种长序列在语料里几乎从未出现过。

于是引入**马尔可夫假设**：不回溯全部历史，只看前面有限的 $n-1$ 个词。这就是 N-gram 的由来。

| 模型 | 假设 | 近似式 |
|------|------|--------|
| Bigram (N=2) | 只看前 1 个词 | $P(w_i|w_1,\dots,w_{i-1})\approx P(w_i|w_{i-1})$ |
| Trigram (N=3) | 只看前 2 个词 | $\approx P(w_i|w_{i-2},w_{i-1})$ |

概率怎么估？**最大似然估计（MLE）**，思想直白到有点朴素：最可能出现的就是数据里出现次数最多的。

$$P(w_i|w_{i-1})=\frac{Count(w_{i-1},w_i)}{Count(w_{i-1})}$$

### 我把手算示例跑了一遍

教材用迷你语料库 `datawhale agent learns`、`datawhale agent works` 算 `datawhale agent learns` 的概率。我写了代码复核，结果一致：

```
语料库分词: ['datawhale', 'agent', 'learns', 'datawhale', 'agent', 'works']  (总词数 6)
所有 bigram 计数: {('datawhale','agent'): 2, ('agent','learns'): 1,
                  ('learns','datawhale'): 1, ('agent','works'): 1}

第一步 P(datawhale)        = 2/6 = 0.333
第二步 P(agent|datawhale)  = 2/2 = 1.000
第三步 P(learns|agent)     = 1/2 = 0.500
连乘 → 0.333 × 1.000 × 0.500 = 0.1667
```

顺手把习题 1 要的 `agent works` 也算了：$P(agent)=2/6=0.3333$，$P(works|agent)=1/2=0.5$，乘起来 **0.1667**——和 `datawhale agent learns` 一样。这个巧合挺有意思，说明这么小的语料库根本区分不出句子好坏。

### 两个致命缺陷

1. **数据稀疏性**：词序列没在语料里出现过，概率估计就是 **0**。这显然不合理（一个句子没出现过 ≠ 它不可能出现）。平滑技术能缓解，但**根除不了**。
2. **泛化能力差**：模型把词当**孤立离散的符号**，不理解语义相似性。见过一万次 `agent learns`，也算不出 `robot learns` 的概率——因为 `robot` 没出现过就是 0。**它不知道 agent 和 robot 是一类东西。**

第 2 条是关键，它直接催生了下一个范式。而且这里有个熟悉的影子：**N-gram 把词当离散符号，这不就是第二章符号主义的老毛病吗**——手写规则覆盖不完，数词对也数不完。

## 二、词嵌入：让"相似"变成可以计算的东西

2003 年 Bengio 等人的**前馈神经网络语言模型**是转折点。核心思想两步：

1. **构建语义空间**：把词汇表里每个词映射成高维连续向量空间中的一个点，这就是**词嵌入（Word Embedding）**。语义相近的词，向量位置也相近——`agent` 和 `robot` 靠得近，`agent` 和 `apple` 离得远。
2. **学从上下文到下一个词的映射**：输入前 $n-1$ 个词的向量，输出词汇表上的概率分布。

关键在于：**词向量不是人工设计的，是训练时自动学出来的**。模型为了完成"预测下一个词"，不断调整每个词向量的位置，最终这些向量就蕴含了语义。

一旦词变成向量，就能用数学度量关系。最常用的是**余弦相似度**：

$$\text{similarity}(\vec{a},\vec{b})=\cos\theta=\frac{\vec{a}\cdot\vec{b}}{|\vec{a}||\vec{b}|}$$

| 夹角 | 余弦值 | 含义 |
|------|--------|------|
| 0° | 1 | 完全相关 |
| 90° | 0 | 毫无关系 |
| 180° | -1 | 完全负相关 |

### 那个著名的 king − man + woman

教材用它说明词向量能捕捉"性别""皇室"这类抽象概念。我跑了一下：

```
king - man + woman = [0.9 0.2]
与 queen 的余弦相似度 = 1.0000
```

**但这里我得记一笔：结果是 1.0000，不是"接近"，是完全相等。** 因为教材给的二维向量是特意构造的——`[0.9,0.8] - [0.7,0.9] + [0.7,0.3]` 恰好等于 `[0.9,0.2]`，也就是 queen 本身。

真实的 word2vec 词向量里，`king - man + woman` 只是**在几百维空间里离 queen 比较近**，绝不会完全相等。所以这个例子能说明"向量可以做语义运算"这个思想，但**不能当作真实效果的证据**。我一开始看到 1.0000 还以为自己算错了，反应过来才意识到是教材为了教学简化构造的。

### 但它还留着 N-gram 的病

神经语言模型解决了泛化，**上下文窗口依然是固定的**——只能看前 $n-1$ 个词，更早的历史直接丢弃。这显然不符合人类理解语言的方式。

## 三、RNN 到 LSTM：给网络装上记忆

**循环神经网络（RNN）**的思路很直观：引入一个**隐藏状态（hidden state）**向量当作短期记忆。每一步读入当前词 + 上一刻的记忆，生成新记忆传给下一刻，信息就这样在序列里不断向后传。

听起来完美，但实践中撞上一个严重问题：**长期依赖问题**。

因为对 RNN 来说，**序列长度就是网络深度**。反向传播时梯度要沿时间步连乘，序列一长，梯度就快速趋零（**梯度消失**）或爆掉（**梯度爆炸**）。梯度消失意味着模型学不到"序列早期的信息如何影响后期输出"——也就是捕捉不了长距离依赖。

**LSTM** 的解法是引入两个东西：

- **细胞状态（Cell State）**：一条独立于隐藏状态的信息通路，让信息在时间步之间更顺畅地传递。
- **门控机制（Gating）**：几个小型神经网络，学习**有选择地**让信息通过。

| 门 | 作用 |
|----|------|
| 遗忘门 Forget Gate | 决定从上一时刻细胞状态里**丢弃**什么 |
| 输入门 Input Gate | 决定把当前输入的哪些新信息**存入**细胞状态 |
| 输出门 Output Gate | 决定根据当前细胞状态**输出**什么到隐藏状态 |

### 但真正的死结不是精度，是速度

LSTM 缓解了长期依赖，可 RNN 家族的**计算方式是串行的**：第 $t$ 步必须等第 $t-1$ 步算完才能开始。

**这意味着无法大规模并行计算。** 处理长序列效率低下，直接限制了模型规模和训练速度的提升。

我觉得这个点特别重要——**Transformer 取代 RNN，主要不是因为效果更好，而是因为它能并行**。在深度学习时代，"能不能用满 GPU"往往比"精度高两个点"更决定成败。这是一个纯粹的工程约束倒逼出的架构革命。

## 四、Transformer：把串行改成并行

2017 年谷歌团队提出 Transformer，**完全抛弃循环结构**，只靠**注意力（Attention）**机制捕捉序列内依赖，从而实现了真正意义上的并行计算。

### Encoder-Decoder：一个分工明确的团队

最初的 Transformer 是为机器翻译设计的：

| 部件 | 任务 | 具体做什么 |
|------|------|-----------|
| **编码器 Encoder** | **理解** | 读取所有输入词元，为每个词元生成富含上下文信息的向量表示 |
| **解码器 Decoder** | **生成** | 参考自己已生成的前文 + "咨询"编码器的理解结果，生成下一个词 |

教材用"自顶向下"的方式讲代码：先搭骨架定义好所有类，再像拼图一样逐个填充。骨架里 `EncoderLayer` 有两个子层（自注意力 + 前馈），`DecoderLayer` 有三个（掩码自注意力 + 交叉注意力 + 前馈）——**解码器多出来的那个交叉注意力，就是它"咨询"编码器的通道**。

### 自注意力：Q、K、V

想象读这句话：`The agent learns because **it** is intelligent.`

读到 `it` 时，为了搞清指代，大脑会不自觉地把更多注意力放在前面的 `agent` 上。**自注意力就是对这种现象的数学建模**：处理每个词时都兼顾句中所有其他词，并分配不同的注意力权重。

实现上给每个词元向量引入三个可学习的角色：

| 角色 | 含义 | 类比 |
|------|------|------|
| **Query (Q)** | 当前词元，主动"查询"其他词元获取信息 | 考题 |
| **Key (K)** | 句中可被查询的词元的"标签/索引" | 资料的索引 |
| **Value (V)** | 词元本身携带的"内容/信息" | 资料的内容 |

三者都由原始词嵌入乘以三个不同的可学习权重矩阵 $W^Q, W^K, W^V$ 得到。

计算四步，教材比喻成一次**高效的开卷考试**，我觉得这个比喻很准：

1. **准备考题和资料**：每个词通过权重矩阵生成自己的 $Q,K,V$
2. **算相关性得分**：用词 $A$ 的 $Q$ 去和句中**所有词（包括自己）**的 $K$ 做点积
3. **稳定化 + 归一化**：除以缩放因子 $\sqrt{d_k}$ 防止梯度过小，再用 Softmax 转成和为 1 的权重
4. **加权求和**：权重乘各自的 $V$ 再相加，得到融合了全局上下文的新表示

$$\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

**为什么要除以 $\sqrt{d_k}$？** 我特意想了一下：$Q$ 和 $K$ 都是 $d_k$ 维，点积是 $d_k$ 个乘积相加。维度越高，点积的数值方差越大，Softmax 会被推到极端（几乎变成 one-hot），梯度就没了。除以 $\sqrt{d_k}$ 就是把方差拉回可控范围。

### 多头注意力：一次做完变成分开做

只做一次注意力（单头），模型可能只学会关注一种关联——比如处理 `it` 时只学会了关注主语。但语言关系是复杂的：指代、时态、从属……

**多头的思想很简单：把 Q、K、V 在维度上切成 $h$ 份，每份独立做一次单头注意力，最后拼接再线性变换整合。**

好比让 $h$ 个"专家"从不同角度审视同一个句子，每人捕捉一种特征关系。代码里对应三个方法：

| 方法 | 形状变换 |
|------|---------|
| `split_heads` | `(batch, seq_len, d_model)` → `(batch, num_heads, seq_len, d_k)` |
| `scaled_dot_product_attention` | 算分数 → 掩码 → softmax → 加权求和 |
| `combine_heads` | 变回 `(batch, seq_len, d_model)` |

注意 `assert d_model % num_heads == 0`——因为 $d_k = d\_model // num\_heads$，必须整除。

掩码那行的写法很值得记：

```python
attn_scores = attn_scores.masked_fill(mask == 0, -1e9)
```

**不是把分数设成 0，而是设成一个极大的负数**。因为接下来要过 Softmax，$e^{-10^9}\approx 0$，这些位置的概率才会真正变成 0。设成 0 反而会给它一个不小的权重——这是我读代码时卡了一下才想通的。

### 前馈网络（FFN）：逐位置加工

注意力层负责**从整个序列动态聚合信息**，FFN 负责**从聚合后的信息里提取更高阶特征**。

名字的关键在"逐位置"：它**独立作用于每个词元向量**，序列多长就调用多少次，但**所有位置共享同一组权重**。既保持了对每个位置独立加工的能力，又大幅减少参数量。

$$\mathrm{FFN}(x)=\max(0, xW_1+b_1)W_2+b_2$$

结构就是两个线性变换夹一个 ReLU。通常 $d_{ff}=4\times d_{model}$，**先扩大再缩小**——这种模式被认为有助于学习更丰富的特征表示。

### Add & Norm：保证训得动

每个子模块都被 `Add & Norm` 包裹，两个部分各解决一个问题：

| 操作 | 公式/做法 | 解决什么 |
|------|----------|---------|
| **残差连接 (Add)** | $\text{Output}=x+\text{Sublayer}(x)$ | **梯度消失**。反向传播时梯度可以绕过子模块直接向前传，网络再深也训得动 |
| **层归一化 (Norm)** | 对单个样本所有特征归一化（均值 0、方差 1） | **内部协变量偏移**。让每层输入分布稳定，加速收敛、提高稳定性 |

有意思的是，残差连接治的还是**梯度消失**——和 LSTM 治的是同一个病。可见这个问题有多难缠，从 RNN 时代一路跟到 Transformer 时代，只是换了个解法：LSTM 用门控，Transformer 用直连捷径。

### 位置编码：注意力是"顺序盲"的

自注意力有个固有问题：**它本身不含任何顺序信息**。对它来说，`agent learns` 和 `learns agent` 完全等价，因为它只关心词元之间的关系，忽略排列。

解法是给每个词元嵌入**额外加上一个代表位置的向量**。而且这个位置向量**不是学出来的，是用固定公式算出来的**：

$$PE_{(pos,2i)}=\sin\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right),\qquad PE_{(pos,2i+1)}=\cos\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$

- $pos$：词元在序列中的位置（0,1,2,…）
- $i$：位置向量的维度索引
- 偶数维用 sin，奇数维用 cos

这样一来，即使两个词元自身嵌入相同（比如句中出现两次 `agent`），因为位置不同，最终输入模型的向量也就独一无二。

代码里有个细节我觉得设计得很妙：

```python
self.register_buffer('pe', pe.unsqueeze(0))
```

**注册成 buffer 而不是 parameter**——因为它不是可学习参数，不需要梯度更新，但要跟着模型一起 `to(device)`。这个区分平时容易忽略。

## 五、Decoder-Only：一次大胆的减法

前面那个完整 Transformer 在端到端任务（比如翻译）上表现出色。但如果目标是造一个**能对话、能创作、能当智能体大脑**的通用模型，或许不需要那么复杂的结构。

Transformer 的设计哲学是"**先理解，再生成**"：编码器深入理解输入全句，形成含全局信息的上下文记忆，解码器基于这份记忆生成译文。

而 OpenAI 做 GPT 时提了个更简单的想法：

> **语言的核心任务，不就是预测下一个最有可能出现的词吗？**

无论是回答问题、写故事还是生成代码，本质上都是在已有文本序列后面一个词一个词地添加最合理的内容。基于这个思想，GPT 做了个大胆的简化：**完全抛弃编码器，只保留解码器。**

### 自回归：文字接龙

Decoder-Only 的工作模式叫**自回归（Autoregressive）**，过程简单到有点朴素：

1. 给起始文本 `Datawhale Agent is`
2. 预测下一个词 `a`
3. **把刚生成的词接到输入末尾** → `Datawhale Agent is a`
4. 基于新输入再预测 → `powerful`
5. 重复，直到生成完整句子或达到停止条件

模型就像在玩文字接龙，不断回顾自己写下的内容，再想下一个字写什么。

### 掩码自注意力：怎么防止"偷看答案"

这里有个我读到时立刻想到的问题：训练时模型一次性拿到完整文本，那它预测第 $t+1$ 个词时，怎么保证不去偷看后面的答案？

答案是**掩码自注意力（Masked Self-Attention）**，机制很巧妙：

- **训练阶段**：文本可以并行送入（这是效率优势），但在算出注意力分数矩阵之后、Softmax 归一化**之前**，应用一个"因果掩码"，把所有位于当前位置**之后**的词元分数替换成一个极大的负数。过 Softmax 后这些位置概率变成 0，于是模型从**数学上被阻止**关注后面的信息。
- **生成阶段**：更直接——未来的词还没生成出来，只能拿已生成的内容当上下文。

**掩码自注意力的真正价值是保证训练方式和生成方式一致。** 如果训练时能看全文、生成时只能看前文，那就是训练与推理不匹配，模型会崩。

（对照上面 `masked_fill(mask == 0, -1e9)` 那行代码—— Decoder-Only 的因果掩码就是这么实现的，一个下三角矩阵。）

### 三个优势

| 优势 | 为什么重要 |
|------|-----------|
| **训练目标统一** | 唯一任务就是"预测下一个词"，**极其适合在海量无标注文本上预训练** |
| **结构简单，易于扩展** | 组件更少 → 更容易规模化。GPT-4、Llama 这些千亿万亿参数的模型都基于这个简洁架构 |
| **天然适合生成任务** | 自回归模式和所有生成式任务（对话、写作、代码）完美契合，**这是它能成为通用智能体基础的核心原因** |

我觉得第一条最关键，它和第二章"预训练解决知识获取瓶颈"直接呼应上了：**正因为目标简单到只需无标注文本，才可能喂进数万亿 token，才可能压出世界知识。** 如果训练需要人工标注，这条路根本走不通。

**减法减出了涌现**——这是我今天最大的意外收获。

## 六、和 LLM 打交道：提示工程

如果把大模型比作能力极强的"大脑"，**提示（Prompt）就是我们和它沟通的语言**。提示工程研究如何设计精准的提示引导出期望的输出。对智能体来说，精心设计的提示能让 Agent 之间协作分工更高效。

### 采样参数：本质是在动概率分布

`Temperature` 这类参数看起来玄，其实本质就一句话：**调整模型对概率分布的采样策略**。

原始 Softmax：$p_i=\frac{e^{z_i}}{\sum_{j=1}^k e^{z_j}}$

**Temperature** 引入温度系数 $T>0$：

$$p_i^{(T)}=\frac{e^{z_i/T}}{\sum_{j=1}^k e^{z_j/T}}$$

- $T$ 变小 → 分布**更陡峭** → 高概率项权重进一步放大 → 输出更保守、重复率更高
- $T$ 变大 → 分布**更平坦** → 低概率项权重提升 → 输出更多样、但可能不连贯

| 温度区间 | 输出特点 | 适用场景 |
|---------|---------|---------|
| 低 `0 ≤ T < 0.3` | 精准、确定 | 事实性任务（问答、数据计算、代码生成）；严谨场景（法律条文、技术文档、学术概念） |
| 中 `0.3 ≤ T < 0.7` | 平衡、自然 | 日常对话（客服、聊天机器人）；常规创作（邮件、产品文案、简单故事） |
| 高 `0.7 ≤ T < 2` | 创新、发散 | 创意任务（诗歌、科幻构思、slogan brainstorm、艺术灵感）；发散性思考 |

**Top-k**：所有 token 按概率排序，取前 $k$ 个组成候选集，再对这 $k$ 个归一化：

$$\hat{p}_i=\frac{p_i}{\sum_{j\in\text{候选集}}p_j}$$

$k=1$ 时输出完全确定，退化成**贪心采样**。

**Top-p**：按概率从高到低排序，逐个累加，直到累积和首次达到或超过阈值 $p$（$\sum_{i\in S}p_{(i)}\geq p$），这些 token 组成"核集合"再归一化。

**Top-p 相比 Top-k 的好处**：Top-k 是**固定截断大小**，Top-p 能**动态适应不同分布的长尾特性**。当分布很集中时 Top-p 可能只留 2 个候选，分布很平坦时可能留 50 个——它对概率分布不均匀的极端情况适应性更好。

**三者协同的优先级：温度调整 → Top-k → Top-p**（分层过滤）。温度先调整体陡峭程度，Top-k 保留最高的 $k$ 个，Top-p 再从中选累积概率 ≥ p 的最小集合。

两个退化情况要记住：

- **温度设为 0** → Top-k 和 Top-p 都变得无关紧要，因为最可能的 token 必然是下一个
- **Top-k 设为 1** → 温度和 Top-p 都变得无关紧要，因为只有一个候选

> 实践提示：通常 Top-k 和 Top-p **二选一即可**，同时设的话实际候选集是两者交集。

这一节对我最有用的认知是：**参数不是玄学，全都是在同一个概率分布上做"重新调整"或"截断"**。想清楚这一点，调参就从背配置变成了按需选择。

### Zero-shot / One-shot / Few-shot

按提供的示例数量分三类，以情感分类为例：

| 类型 | 给几个示例 | 提示长什么样 |
|------|-----------|-------------|
| **零样本 Zero-shot** | 0 个 | 直接下指令：`文本:... 情感:` |
| **单样本 One-shot** | 1 个 | 先给一个完整"问题-答案"对示范格式和风格，再问新的 |
| **少样本 Few-shot** | 多个 | 给涵盖不同情况的多个示例，让模型理解任务的细节、边界和细微差别 |

Zero-shot 之所以可行，靠的是**预训练后获得的强大泛化能力**。

### 指令调优：从"续写"到"听懂人话"

早期 GPT-3 主要是**文本补全模型**，擅长续写，但不一定能理解并执行人类指令。

**指令调优（Instruction Tuning）**用大量"指令-回答"格式的数据对预训练模型进一步训练。之后模型就能更好地理解并遵循指令。

对比一下差别有多直接：

```
# 对"文本补全"模型 —— 你得用少样本提示"教会"它做什么
这是一段将英文翻译成中文的程序。
英文:Hello
中文:你好
英文:How are you?
中文:

# 对"指令调优"模型 —— 直接下指令
请将下面的英文翻译成中文:
How are you?
```

教材特意点明：**我们今天用的所有模型（ChatGPT、DeepSeek、Qwen）都是经过指令调优的**。这也解释了第二章里"指令遵循"为什么被列为涌现能力之一——它是被专门训出来的。

### 基础技巧 + 思维链

**角色扮演**：赋予特定角色，引导回答风格、语气和知识范围。

```
你现在是一位资深的Python编程专家。请解释一下Python中的GIL，要让一个初学者也能听懂。
```

一句话同时约束了三件事：专业深度（资深专家）、表达水平（初学者能懂）、话题范围（GIL）。

**上下文示例**：和少样本思想一致，在提示里给清晰的输入输出示例，处理复杂格式或特定风格时特别有效。教材的例子是要求严格按 JSON 格式抽取产品信息——**给一个完整的输入输出对，比写十句格式说明都管用**。

**思维链（Chain-of-Thought, CoT）**：对需要逻辑推理、计算或多步骤思考的问题，直接要答案容易出错。CoT 通过引导模型"一步一步思考"提升推理能力。

实现关键简单得离谱：**在提示里加一句"请逐步思考"或"Let's think step by step"**。

教材的例子是算两个赛季的总胜率，模型会输出：

```
第一步: 80场 × 60% = 48场
第二步: 总比赛数 = 80 + 15 = 95场；总胜利数 = 48 + 12 = 60场
第三步: 总胜率 = (60/95) × 100% ≈ 63.16%
```

显式展示推理过程有两个好处：**更容易得出正确答案**，而且**回答更可信、更易于检查和纠正**。

第二个好处对智能体开发特别重要——Agent 的规划模块本质上就是在做 CoT，把宏观目标拆成可执行步骤，而且拆出来的中间步骤是**可以被人和工具审查的**。这又回到了第二章那条"可解释性"的主线。

## 七、分词：最容易被忽视的底层细节

计算机只能理解数字，所以文本喂给模型前必须转成数字格式。这个过程叫**分词（Tokenization）**，执行它的是**分词器（Tokenizer）**，切出来的最小单元叫**词元（Token）**。

### 为什么不能简单按词或按字符切

| 策略 | 好处 | 致命问题 |
|------|------|---------|
| **按词分词 Word-based** | 直观 | ① **词表爆炸 + 未登录词（OOV）**：词汇量巨大，词表难管理，遇到没见过的词（如 `DatawhaleAgent`）直接抓瞎<br>② **语义关联缺失**：`look`/`looks`/`looking` 被当成三个完全不同的词元，尽管核心含义相同；低频词学不好 |
| **按字符分词 Character-based** | 词表极小，**无 OOV 问题** | 单个字符大多不具备独立语义，模型要花更多精力学怎么把字符组成词，**学习效率低下** |

两个极端都不行，于是现代 LLM 普遍采用**子词分词（Subword Tokenization）**：

> 常见词（如 `agent`）保留为完整词元，不常见词（如 `Tokenization`）拆成有意义的子词片段（`Token` + `ization`）。

**既控制了词表大小，又能通过组合子词理解和生成新词。** 这个思路和第二章"分布式表示"是同一种智慧——不穷举，而是学可组合的基本单元。

### BPE：一个贪心的合并过程

**字节对编码（Byte-Pair Encoding）**是最主流的子词算法之一，GPT 系列就用它。三步：

1. **初始化**：词表 = 语料里出现过的所有基本字符
2. **迭代合并**：统计所有相邻词元对的频率，把**频率最高的一对**合并成新词元，加入词表
3. **重复**第 2 步，直到词表达到预设大小

### 我把 BPE 也跑了一遍，发现一个教材没提的问题

语料 `{"hug":1, "pug":1, "pun":1, "bun":1}`，构建大小为 10 的词表。教材说合并顺序是 `(u,g) → (ug,</w>) → (u,n) → (un,</w>)`。

我跑代码复核，最终词表一致：`['h ug</w>', 'p ug</w>', 'p un</w>', 'b un</w>']`。

**但第一次合并时我打印了全部候选对的频次，发现问题：**

```
第 1 次合并前，相邻对频次:
{('h','u'): 1, ('u','g'): 2, ('g','</w>'): 2, ('p','u'): 2,
 ('u','n'): 2, ('n','</w>'): 2, ('b','u'): 1}
```

**有五个对并列最高频（都是 2）！** 教材选了 `('u','g')`，但 `('g','</w>')`、`('p','u')`、`('u','n')`、`('n','</w>')` 频次完全相同。

而代码用的是：

```python
best = max(pairs, key=pairs.get)
```

`max()` 遇到并列时返回**第一个遇到的**，也就是依赖 dict 的插入顺序——而插入顺序又依赖语料里词的出现顺序。**换个语料顺序，第一次合并可能就选 `('u','n')` 了，后续整个词表都会不同。**

这个发现让我有点兴奋，因为**它和昨天 Task02 里 ELIZA 的教训一模一样**：

> ELIZA 的规则顺序是一份隐式契约——`I am not` 必须排在 `I am` 前面，没有任何机制保证，全靠开发者自觉。

BPE 这里也是：**并列时的破局规则是隐式的，没有任何文档或断言告诉你，全靠 dict 插入顺序碰巧正确。** 真实工业级实现会显式定义 tie-breaking 规则（比如按字典序），但教材这段简化代码没有。

**动手跑一遍才能发现的东西，又比看代码多了一条。**

### 后续两个变体

| 算法 | 谁在用 | 和 BPE 的区别 |
|------|--------|--------------|
| **WordPiece** | Google BERT | 合并标准不是"最高频率"，而是"**能最大化提升语料库的语言模型概率**"——优先合并让整个语料"通顺度"提升最大的词元对 |
| **SentencePiece** | Llama 系列 | **把空格也视作普通字符**（通常用 `_` 表示）。这让分词和解码**完全可逆**，且**不依赖特定语言**（不需要知道中文不用空格分词） |

SentencePiece 那个设计我觉得很聪明：**把空格降级为普通字符，就顺便解决了中文日文这类无空格语言的分词问题**，一个改动同时换来可逆性和语言无关性。

### 分词器对开发者的实际意义

教材强调理解算法细节不是目的，但作为智能体开发者必须理解分词的实际影响——**直接关系到性能、成本和稳定性**：

| 影响 | 具体说明 |
|------|---------|
| **上下文窗口限制** | 窗口（8K、128K）是按 **Token 数量**算的，不是字符数或单词数。同一段话在不同语言、不同分词器下 Token 数可能差巨大。**精确管理输入长度是构建长时记忆智能体的基础** |
| **API 成本** | 大多数模型 API **按 Token 计费**。了解文本会被怎么分词，是预估和控制智能体运行成本的关键 |
| **模型表现异常** | 有时模型的奇怪行为根源就在分词 |

第三点教材举的例子我印象很深：**模型可能很擅长算 `2 + 2`，但对 `2+2`（无空格）就可能出错**，因为后者可能被分词器当成一个独立的不常见词元。同样，**一个词首字母大小写不同，也可能被切成完全不同的 Token 序列**，从而影响理解。

这对写提示词和解析模型输出都是实实在在的坑。我昨天调 ELIZA 时撞的"标点污染"（`exhausted.?`）本质上是同一类问题——**底层是字符串/符号操作，而你以为它在理解语义**。

## 八、本地部署与模型选型

### 用 Hugging Face 跑一个开源模型

第一章是通过 API 交互，快速便捷但**不是唯一方式**。对需要处理敏感数据、离线运行或精细控制成本的场景，本地部署至关重要。

教材选的小模型是 `Qwen/Qwen1.5-0.5B-Chat`（约 5 亿参数），体积小、适合入门。

```bash
pip install transformers torch
```

核心是两个 Auto 类：`AutoModelForCausalLM` 和 `AutoTokenizer`，会自动加载匹配的权重和分词器。

完整四步流程：

```python
# 1. 加载（会自动从 HF Hub 下载，取决于网速）
device = "cuda" if torch.cuda.is_available() else "cpu"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).to(device)

# 2. 构造对话模板 + 编码
messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "你好，请介绍你自己。"}
]
text = tokenizer.apply_chat_template(messages, tokenize=False,
                                     add_generation_prompt=True)
model_inputs = tokenizer([text], return_tensors="pt").to(device)

# 3. 生成
generated_ids = model.generate(model_inputs.input_ids, max_new_tokens=512)

# 4. 截掉输入部分，只解码新生成的，再还原成文本
generated_ids = [out[len(inp):] for inp, out in
                 zip(model_inputs.input_ids, generated_ids)]
response = tokenizer.batch_decode(generated_ids, skip_special_tokens=True)[0]
```

几个我觉得容易忽略的点：

- **`apply_chat_template`**：Qwen1.5-Chat 遵循特定对话模板，不能直接把 messages 拼成字符串塞进去。编码后的 `input_ids` 里能看到 `151644`、`151645` 这类特殊 token，就是模板的角色标记。
- **第 4 步的截断**：`generate()` 返回的是**输入 + 生成**的完整序列，必须用 `[len(input_ids):]` 切掉输入部分，否则会把问题重复一遍。
- **`skip_special_tokens=True`**：不然输出里会带 `<|im_end|>` 之类的标记。
- **`max_new_tokens`** 控制最多生成多少新 Token——这直接关系到上一节说的成本和上下文窗口。

教材跑出来的回答是模型自报家门「我叫通义千问，是由阿里云研发的预训练语言模型……」。

> **这部分我还没实际跑。** 要下载模型权重，我打算按习题 4 的要求换成 `Qwen3-0.6B` 单独做一次完整实验，顺带调采样参数、对比提示策略，跑完把真实输出补进这一节。

### 模型选型的八个维度

教材特别强调：**选型不是简单追求"最大最强"，而是在性能、成本、速度、部署方式之间权衡的决策过程。**

| 维度 | 关键考量 |
|------|---------|
| **性能与能力** | 最核心。不同模型擅长不同任务——有的长于逻辑推理和代码，有的胜在创意写作或多语言翻译。可参考 LMSys Chatbot Arena Leaderboard |
| **成本** | 闭源看 API 调用费（按 Token 计费）；开源看本地硬件（GPU、内存）和运维 |
| **速度（延迟）** | 实时交互场景（客服、游戏 NPC）至关重要。轻量或优化过的模型延迟更优 |
| **上下文窗口** | 一次能处理的 Token 上限。需要理解长文档、分析代码库或维持长期对话记忆的，得选 128K 或更高 |
| **部署方式** | API 最便捷但数据要发给第三方、受服务商条款限制；本地部署保证隐私和自主可控，但技术和硬件要求高 |
| **生态与工具链** | 流行程度决定周边生态成熟度：社区支持、教程、微调工具、兼容框架（LangChain、LlamaIndex、HF Transformers）。**活跃的社区意味着遇到问题更容易找到解法** |
| **可微调性与定制化** | 处理特定领域数据时至关重要。开源模型通常灵活性更大 |
| **安全性与伦理** | 偏见、毒性、幻觉方面的表现，以及厂商在负责任 AI 上的投入。**面向公众或涉及敏感信息时不可忽视** |

教材很诚实地加了一句提醒：大模型迭代极快，文中具体版本和性能数据可能随时间变化，且只列举了部分工作并不完整——**更应关注核心技术特点、发展趋势和通用选型原则**。这个态度我很认同，也是我做笔记时不去死记版本号的原因。

### 闭源与开源两大阵营

**闭源**（代表当前技术前沿，提供稳定易用的 API）：

| 系列 | 特点 |
|------|------|
| **OpenAI GPT** | GPT-3 开启大模型时代 → ChatGPT 引入 **RLHF** 实现意图对齐 → GPT-4 开启多模态 → GPT-5 无缝处理文本/音频/图像，实时语音对话表现出色 |
| **Google Gemini** | **原生多模态**代表，统一处理文本、代码、音视频、图像；**超长上下文窗口**是优势。Ultra（最强）/ Pro（广泛任务）/ Nano（设备端）。2.5 系列进一步提升推理和窗口，Flash 主打速度和成本效益 |
| **Anthropic Claude** | **从设计之初就把 AI 安全放首位**，以处理长文档、减少有害输出、遵循指令的可靠性闻名，深受企业级青睐。3 系列：Opus（最智能）/ Sonnet（平衡）/ Haiku（最快最紧凑） |
| **国内主流** | 百度文心一言、腾讯混元、华为盘古、讯飞星火、月之暗面等，**中文处理有天然优势**，深度赋能本土产业 |

**开源**（最高灵活性、透明度、自主性，可本地部署和定制微调）：

| 系列 | 特点 |
|------|------|
| **Meta Llama** | 开源大模型的重要里程碑，**开放许可 + 强社区支持**，成为许多衍生项目和研究的基座。**Llama 4**（2025-04）是 Meta 首批采用**混合专家（MoE）架构**的模型——只激活处理特定任务所需的部分，显著提升计算效率。三款定位分明：**Scout**（1000 万 token 上下文，长文档 + 移动端）、**Maverick**（多模态，编码/复杂推理/多语言）、**Behemoth**（多项 STEM 基准超越对手，Meta 最强） |
| **Mistral AI** | 法国公司，以"**小尺寸、高性能**"闻名。Mistral Medium 3.1（2025-08）在代码生成、STEM 推理、跨领域问答上准确率和速度均显著提升；具备原生多模态，内置"语调适配层"帮企业实现符合品牌调性的输出 |
| **国内开源** | 阿里**通义千问 Qwen**、清华 + 智谱 **ChatGLM**，中文能力强，社区活跃 |

**MoE 这个点值得单独记一下**：它不是把模型做得更大，而是**让每次推理只激活一部分专家**。这等于在"参数量"和"计算量"之间解耦——总参数很大（知识容量大），但单次前向的计算量只相当于一个小模型。这算是缩放法则之外的另一条提升路径。

教材的总结很到位：**闭源提供"开箱即用"的便捷，开源赋予"随心所欲"的定制自由。**

## 九、缩放法则与局限性：能力边界在哪

### 缩放法则：投入和产出是可以预测的

**缩放法则（Scaling Laws）**揭示模型性能与**参数量、数据量、计算资源**之间存在**可预测的幂律关系**。

具体发现：在**对数-对数坐标系**下，模型性能（通常用损失 Loss 衡量）与这三个因素都呈现**平滑的幂律关系**。

**这个"平滑"是关键**：只要持续、按比例增加这三要素，性能就会**可预测地、平滑地**提升，**不会出现明显瓶颈**。这为大模型设计提供了清晰指导——在资源允许范围内尽可能扩大规模。

### Chinchilla 定律：不是越大越好

早期研究侧重加参数量，但 DeepMind 2022 年的 **Chinchilla 定律**做了重要修正：

> 在给定计算预算下，**模型参数量和训练数据量之间存在最优配比**。最优模型应该比之前普遍认为的**更小**，但要用**多得多的数据**训练。

教材给的例子很有说服力：**700 亿参数的 Chinchilla，因为用了比 GPT-3（1750 亿参数）多 4 倍的数据训练，性能反而超越了后者。**

这纠正了"越大越好"的片面认知，**强调数据效率的重要性**，并指导了后续许多高效大模型（如 Llama 系列）的设计。

我觉得这个定律的哲学意味和第二章那条"可解释性 vs 鲁棒性"的取舍很像：**资源有限时，永远存在一个最优分配点，盲目堆单一维度是低效的。**

### 能力涌现：缩放法则最惊奇的产物

**能力涌现**指模型规模达到一定阈值后，**突然展现出小规模模型完全不存在或表现不佳的全新能力**。

教材列举的涌现能力：**链式思考（CoT）、指令遵循、多步推理、代码生成**——都是在参数量达到**数百亿甚至千亿级别**后才显著出现的。

> 这种现象表明，大语言模型不仅仅是简单地记忆和复述，它们在学习过程中可能形成了某种更深层次的抽象和推理能力。

**对智能体开发者的直接含义：选择一个足够大规模的模型，是实现复杂自主决策和规划能力的前提。** 换句话说，小模型做不了 Agent 的大脑——不是提示词写得不好，是能力根本没涌现出来。

注意这里的"涌现"和第二章那个**又是不同的机制**：

| 出处 | 涌现的含义 |
|------|-----------|
| 心智社会（1986） | 大量简单体**局部交互**自发产生复杂行为 |
| 缩放法则（本章） | **规模跨过阈值**后出现全新能力 |

名字一样，机制完全不同。这已经是教材里"涌现"第二次以不同含义出现了，别混。

### 模型幻觉：最要命的局限

**幻觉（Hallucination）**指生成的内容与客观事实、用户输入或上下文相矛盾，或生成不存在的事实、实体、事件。

**本质是：模型在生成过程中过度自信地"编造"信息，而非准确检索或推理。**

三种类型：

| 类型 | 表现 |
|------|------|
| **事实性幻觉 Factual** | 生成与现实世界事实不符的信息 |
| **忠实性幻觉 Faithfulness** | 摘要、翻译等任务中，生成内容未忠实反映源文本含义 |
| **内在幻觉 Intrinsic** | 生成内容与**输入信息直接矛盾** |

**成因（三方面共同作用）**：

1. **训练数据本身可能包含错误或矛盾信息**
2. **自回归生成机制决定了它只是在预测下一个最可能的词元，没有内置事实核查模块** ← 我认为这条是根本原因
3. 面对复杂推理任务时，可能在**逻辑链条中出错**，从而编造错误结论

第 2 条和第 5 节直接呼应上了：**"预测下一个词"这个训练目标带来了规模化和涌现，代价就是它压根不关心真假。** 一个词接得通顺，不等于它是对的。这不是 bug，是这个范式的固有属性。

教材举的智能体场景例子很实际：**一个旅游规划 Agent，可能推荐一个现实中不存在的景点，或者预订一个航班号错误的机票。**

另外还有两个挑战：

- **知识时效性不足**：模型掌握的知识止于训练数据收集时的最新材料，之后的事件、新概念、最新事实一概无法感知
- **训练数据偏见**：数据包含人类社会的偏见和刻板印象，模型学习时不可避免会吸收并反映

### 缓解幻觉的三层手段

| 层面 | 方法 |
|------|------|
| **数据层** | 高质量数据清洗、引入事实性知识、**RLHF**（强化学习与人类反馈），从源头减少幻觉 |
| **模型层** | 探索新架构，或让模型**能表达自己对生成内容的不确定性** |
| **推理与生成层** | ① **检索增强生成 RAG**（目前最有效的方法之一）<br>② **多步推理与验证**（引导多步推理，每步自我检查或外部验证）<br>③ **引入外部工具**（搜索引擎、计算器、代码解释器获取实时信息或精确计算） |

**RAG 的原理**：生成之前先从外部知识库（文档数据库、网页）检索相关信息，把检索结果作为上下文，**引导模型生成基于事实的回答**。

教材的结论很务实：**幻觉短期内难以完全消除，但通过上述策略可以显著降低发生频率和影响。**

这里我又想到了第二章那条主线——**RAG 和工具调用本质上是在把符号主义时代的"外挂知识库"请回来**：权重负责通用推理，外部知识库负责可溯源的事实。我在 Task02 习题 6 里写过这个观察，现在从幻觉的角度看更清楚了：**外挂知识库不是可选优化，而是压制幻觉的必需品**，因为自回归范式本身没有事实核查能力。

而"多步推理与验证"正是 Agent 架构的强项——**感知-思考-行动-观察的闭环天然提供了"行动后验证"的机会**。这是为什么 Agent 比单次 LLM 调用更可靠的一个结构性原因。

### 验证 1：Bigram 概率 ✅

教材结果 0.167，我算出 **0.1667**，一致。顺便算了习题 1 要的 `agent works` = **0.1667**。

### 验证 2：BPE 合并过程 ⚠️ 发现问题

最终词表和教材一致：`['h ug</w>', 'p ug</w>', 'p un</w>', 'b un</w>']`

**但第一次合并时有五个候选对并列频次 2**：`('u','g')`、`('g','</w>')`、`('p','u')`、`('u','n')`、`('n','</w>')`。教材选了 `('u','g')`，而代码里 `max(pairs, key=pairs.get)` 在并列时返回第一个遇到的，**依赖 dict 插入顺序，也就是依赖语料里词的出现顺序**。

换个语料顺序，第一次合并可能就选别的对，后续整个词表都会不同。**这是一个隐式的、无文档、无断言保证的 tie-breaking 规则。**

和 Task02 里 ELIZA「规则顺序是隐式契约」是同一类问题。工业级实现会显式定义破局规则，教材这段简化代码没有。

## 十一、今天想通的几件事

1. **Transformer 战胜 RNN，主要靠并行而不是精度。** RNN 的串行计算（第 $t$ 步等第 $t-1$ 步）让它无法用满 GPU，这直接限制了规模。**在深度学习时代，工程约束往往比算法优劣更能决定架构生死。**

2. **Decoder-Only 是"减法减出涌现"。** 前面每次范式更替都是补缺陷，只有这次是主动砍掉编码器。而正因为目标简化到"预测下一个词"，才可能吃无标注数据、才可能堆到千亿参数、才可能涌现。**简单的目标 + 海量数据 + 大规模 = 意外强大的能力。**

3. **"预测下一个词"这个目标是把双刃剑。** 它带来了规模化和涌现（第 5 节），也直接导致了幻觉（第 9 节）——因为这个目标**只关心接得通不通顺，压根不关心真不真**。理解这一点，就不会指望靠提示词彻底消除幻觉，而是会去做 RAG 和工具验证。

4. **残差连接和 LSTM 门控治的是同一个病（梯度消失），只是解法不同。** 一个用直连捷径，一个用门控通路。这个问题从 RNN 时代一路跟到 Transformer 时代。

5. **分词器是智能体开发者的隐形成本中心。** 上下文窗口按 Token 算、API 按 Token 计费、`2+2` 和 `2 + 2` 可能被切成不同 token。**这三条每一条都会直接影响 Agent 的性能、成本和稳定性**，而它们藏在最底层，最容易被忽略。

6. **Chinchilla 定律和"可解释性 vs 鲁棒性"是同一种智慧。** 资源有限时永远存在最优分配点，盲目堆单一维度低效。参数量和数据量要配比，就像鲁棒性和可解释性要权衡。

7. **"涌现"这个词在教材里已经是第三种含义了。** 心智社会的涌现（简单体局部交互）、缩放法则的涌现（规模跨阈值）。名字一样机制完全不同，这个坑我已经在 Task02 记过一次，这次又踩了一遍边缘——**术语复用是学习 AI 领域最大的障碍之一**。

## 十二、今天的收获

1. 理清了语言模型的完整演进链：**N-gram → 神经语言模型 → RNN/LSTM → Transformer → Decoder-Only**，以及每一跳到底在补什么缺陷。
2. 会算 Bigram 概率了，也理解了 MLE 的朴素思想和 N-gram 的两个致命缺陷（稀疏性、无泛化）。
3. 搞懂了 Transformer 五个核心组件各自的职责：**自注意力**（动态聚合全局信息）、**多头**（多专家多角度）、**FFN**（逐位置提取高阶特征）、**Add & Norm**（保证训得动）、**位置编码**（补上顺序信息）。
4. 理解了自注意力的 Q/K/V 机制和那个公式，也明白了为什么要除以 $\sqrt{d_k}$、为什么掩码要填 `-1e9` 而不是 0。
5. 分清了 Decoder-Only 和 Encoder-Decoder 的区别，以及**掩码自注意力如何保证训练与生成方式一致**。
6. 采样参数不再是玄学：温度调陡峭程度、Top-k 固定截断、Top-p 动态核集合，优先级是**温度 → Top-k → Top-p**，还有两个退化情况。
7. 记住了 Zero-shot / One-shot / Few-shot 的区别，以及**指令调优如何让模型从"续写"变成"听懂指令"**。
8. 理解了子词分词为什么是必然选择，BPE 的贪心合并逻辑，以及 WordPiece / SentencePiece 的改进点。
9. 掌握了本地部署的四步流程和三个易错点（chat template、截断输入、skip_special_tokens）。
10. 记住了模型选型的八个维度和闭源/开源两大阵营的定位差异，以及 **MoE 是"参数量与计算量解耦"的另一条路径**。
11. 理解了缩放法则的幂律关系、**Chinchilla 的最优配比修正**、能力涌现对 Agent 选型的直接含义。
12. 搞清了幻觉的三种类型、三个成因（**自回归无事实核查是根本**）和三层缓解手段。

### 三章连起来看

到现在三章的脉络已经很清楚了：

| 章 | 回答的问题 | 核心结论 |
|----|-----------|---------|
| 第一章 | 智能体是什么、怎么跑起来 | Agent Loop = 感知-思考-行动-观察 |
| 第二章 | 它为什么长成这个样子 | 七十年三大思潮合流，神经-符号结合 |
| **第三章** | **那个"大脑"内部怎么运作** | **Decoder-Only + 预测下一个词 → 规模化 → 涌现，代价是幻觉** |

而**有一条线三章都在**：**可解释性的取舍**。

- 第二章：符号主义规则完全可读，但覆盖不完；预训练权重不可读，但鲁棒
- 第三章上半：**CoT 让推理过程显式可见**——这是在不可读的权重之上，人为造出一层可读性
- 第三章下半：**RAG 强制引用溯源 + 工具验证**——这是把符号主义的"外挂知识库"请回来补事实性

所以我的判断是：**现代智能体架构不是放弃了可解释性，而是把它从"模型内部"搬到了"模型边界"**。权重里发生什么我们永远不知道，但 CoT 的中间步骤、RAG 的检索来源、工具调用的输入输出——**这些都是可审查的**。Agent 框架的工程价值，很大一部分就在于制造这些可审查的接口。
